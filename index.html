01 / ENGINEERING OVERVIEW

Built to understand every layer.

Rather than loading official pretrained Mixtral weights, the project implements its own Mixtral-inspired decoder and trains it through two explicitly separated stages.

◈01 / ATTENTION

Grouped-query attention

Six query heads and two key/value heads, rotary position embeddings and causal scaled dot-product attention.

GQARoPESDPA
✳02 / MIXTURE-OF-EXPERTS

Top-2 sparse routing

Per-token routing across four independent SwiGLU experts with normalized weights and a balancing objective.

4 expertsTop-2Router loss
∑03 / MODEL TRAINING

Full-model optimization

AdamW updates embeddings, attention, expert weights, router and output head. No LoRA or frozen backbone.

AdamWRMSNormFull SFT
⌘04 / DATA PIPELINE

Healthcare-first datasets

Biomedical text for pretraining, followed by separate medical instruction data and completion-only supervision.

Stage 1 processed 2.56 million tokens (5,000 steps × 512 tokens, per its training manifest). Pretraining cut PubMed loss from 10.31 to 6.35 nats per token. SFT then lowered Q&A loss from 6.54 to 5.53 while PubMed loss rose to 6.50: the model specialised in the Q&A format.

Per-step loss was printed to the console during these two runs and not saved (the run folders keep only the final checkpoint and a manifest), so there is no step-by-step curve to show yet. The training scripts now write every logged step to metrics.jsonl; the next run will publish its full curve here.

How this was measured, and the limits
  • What it means. Medical SFT lowers held-out Q&A perplexity by 64% (692 → 253; paired 95% CI of the ratio 0.34–0.39). On PubMed text the pretrained checkpoint stays better (572 vs 667): SFT trades some general biomedical fit for the Q&A format. On MedMCQA the SFT model is not distinguishable from chance and the pretrained model is slightly above chance, but below always answering the most common letter (38%): expected for 38.8M parameters. The clearest improvement to make next: only 9% of held-out Q&A examples keep the whole question inside the 128-token training window, so SFT mostly learns answer style without the question. Fine-tuning with longer sequences (for example 512 tokens) should help most.
  • Held-out data. PubMed: the first 40 articles in licensed_pubmed-0000.json.gz that pass the training filters (clinical keywords, CC0/CC-BY licence) and fall in the 2% validation partition of stable_partition (2,407 scanned). Q&A: the first 80 medical-o1 (en) rows in the 5% validation bucket of bucket_for_question. Both splits use BLAKE2b with seed 42, re-implemented in JavaScript and checked against Python's hashlib.
  • Scoring. PubMed uses the packed pretraining window (128 scored tokens per article, no <bos>). Q&A mirrors tokenize_example(seq_len=128): the chat template, answer-only loss, and the prompt trimmed from the left. Because answers are long, only 9% of these examples keep the whole question inside the 128-token window, which is also true of training.
  • MedMCQA. The first 150 validation questions; each option is scored by its mean log-probability per token after the question (cloze style, options not shown). Wilson 95% intervals.
  • Engine. The playground's float32 JavaScript implementation of the published weights (Hugging Face revisions bb8e91ae and 0a157beb), not PyTorch. Uncertainty: 2,000-sample bootstrap over items.
  • Not a clinical evaluation. These numbers measure language modelling on held-out text. They say nothing about medical safety or correctness.
